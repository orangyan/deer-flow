# 02 功能结构

## 核心功能模块全览

```
DeerFlow 功能体系
├── Skills（技能系统）          Markdown 文件定义工作流，按需加载
├── Sub-Agents（子 Agent）      最多 3 个并行，ThreadPool 独立隔离
├── Sandbox（沙箱执行）         Local / Docker / K8s 三种模式
├── Memory（长期记忆）          结构化 Facts + 置信度评分，跨会话持久
├── IM Channels（IM 接入）      Telegram / Slack / 飞书 / 企业微信 / 微信
├── MCP（协议扩展）             stdio / SSE / HTTP，支持 OAuth
├── File Upload（文件上传）     PDF/PPT/Word/Excel 自动转 Markdown
└── WebUI（Web 界面）           Next.js 16，实时流式，多语言
```

## Skills（技能系统）

Skills 是 DeerFlow 最具特色的功能，**用 Markdown 文件定义结构化工作流和最佳实践**。

### 设计理念

- 技能 = 一个 `SKILL.md` 文件，包含 YAML frontmatter + 自然语言指导
- 按需渐进加载（Progressive Loading）：只有用到时才注入上下文，节省 token
- 系统提示中仅显示技能目录，Agent 主动读取感兴趣的技能全文

| Skill | 功能描述 |

| `ppt-generation` | PPT 幻灯片生成 |
| `image-generation` | AI 图像生成 |
| `video-generation` | AI 视频生成 |

| `frontend-design` | 前端页面设计（HTML/CSS/JS）|

## Sub-Agents（子 Agent 系统）

### 能力

- Lead Agent 通过 `task()` 工具动态拉起子 Agent
- 最多同时运行 3 个并行子 Agent（`SubagentLimitMiddleware` 强制限制）
- 内置两种 Agent 类型：
  - `general-purpose`：通用型（带网络搜索、文件操作、沙箱执行）
  - `bash`：命令行专家型（仅沙箱执行）
- 支持自定义子 Agent 类型
- 每个子 Agent 默认 15 分钟超时
- 子 Agent 上下文完全隔离（不继承父 Agent 消息历史）

### 适用场景

```
# 并行研究场景
Lead Agent: "帮我分析三大云服务商的对比"
  ├── task("分析 AWS 优劣势", subagent_type="general-purpose")
  ├── task("分析 Azure 优劣势", subagent_type="general-purpose")
  └── task("分析 GCP 优劣势", subagent_type="general-purpose")
```

## Sandbox（沙箱执行环境）

### 虚拟路径系统

Agent 通过虚拟路径访问文件，框架自动映射到真实物理路径：

```
Agent 看到的路径              真实物理路径
/mnt/user-data/uploads/   → .deer-flow/users/{uid}/threads/{tid}/user-data/uploads/
/mnt/user-data/workspace/ → .deer-flow/users/{uid}/threads/{tid}/user-data/workspace/
/mnt/user-data/outputs/   → .deer-flow/users/{uid}/threads/{tid}/user-data/outputs/
```

### 沙箱模式

| 模式 | 类 | 特点 |
|------|-----|------|
| Local | `LocalSandboxProvider` | 开发调试，直接执行，默认禁用 bash |
| Docker | `AioSandboxProvider` | 生产推荐，容器完全隔离 |
| K8s | `AioSandboxProvider` + provisioner | 高并发，Pod 级隔离 |

### Agent 可执行操作

- 执行 bash 命令（在沙箱内）
- 读取/写入文件
- 安装 Python 包（`pip install`）
- 查看图片（视觉模型支持）
- 访问网络（沙箱内可控制）

## Memory（长期记忆系统）

### 记忆结构

每个用户的 `memory.json` 文件包含：

```json
{
  "userContext": "用户偏好、工作背景摘要",
  "workContext": "当前项目/任务的上下文",
  "summary": "近期对话摘要",
  "facts": [
    {
      "content": "用户偏好使用 Python",
      "category": "preference",   // preference/knowledge/context/behavior/goal
      "confidence": 0.9,
      "updated_at": "..."
    }
  ]
}
```

### 记忆注入

每次对话开始时，注入到系统提示的 `<memory>` 块中：
- Top-15 Facts（按 confidence 排序）
- userContext 摘要
- workContext 摘要
- 最多 2000 token

### 记忆更新机制

- 对话结束后，`MemoryMiddleware` 将消息入队
- 30 秒 debounce 防止频繁写入
- 后台 LLM 调用：从对话中提取新 Facts、更新摘要
- 原子写入（temp file + rename，防止数据损坏）

### 记忆去重

- whitespace 归一化后去重
- 防止 `" memory"` vs `"memory"` 等空格差异导致的重复

## IM Channels（即时通讯接入）

| 渠道 | 传输协议 | 特性 |
|------|----------|------|
| Telegram | Long-polling | 完整媒体支持，inline buttons |
| Slack | Socket Mode | Thread 隔离，Markdown 渲染 |
| 飞书/Lark | WebSocket | 流式输出，CardKit，全球域 |
| 企业微信 | WebSocket | 完整媒体，QQ 群聊 |
| 微信 | Tencent iLink | 语音、图片、文件 |

每个渠道通过 `assistant_id` 路由到指定 Agent，支持不同渠道用不同 Agent。

## MCP（Model Context Protocol）

- 标准 MCP 协议接入外部工具
- 支持传输方式：`stdio`、`SSE`、`HTTP`
- HTTP 支持 OAuth 认证
- 运行时可通过 API 修改配置（不需重启）
- 配置在 `extensions_config.json` 的 `mcpServers` 字段

## File Upload（文件上传与处理）

### 支持格式

| 格式 | 处理方式 |
|------|----------|
| PDF | markitdown 转 Markdown |
| PPT/PPTX | markitdown 转 Markdown |
| Word/DOCX | markitdown 转 Markdown |
| Excel/XLSX | markitdown 转 Markdown |
| 图片 | 直接传递给视觉模型（base64）|
| 纯文本 | 直接读取 |

### 上传流程

```
用户上传文件
  → 验证路径安全性（防目录穿越）
  → 存储到 .deer-flow/.../uploads/
  → 若是文档格式 → markitdown 转换为 .md
  → 返回虚拟路径给前端
  → 下次 Agent 运行时，UploadsMiddleware 注入文件列表
  → Agent 通过 read_file() 读取
```

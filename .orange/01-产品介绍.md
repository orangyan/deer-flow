# 01 产品介绍

## 项目是什么

**DeerFlow**（**D**eep **E**xploration and **E**fficient **R**esearch **Flow**）是由字节跳动开源的 **Super Agent Harness**（超级 Agent 运行时框架）。2.0 版本于 2026 年 2 月 28 日发布后，登上 GitHub Trending 第一名。

它不是一个普通的 AI 聊天框架，而是一个完整的 Agent 执行基础设施，让 AI Agent 可以真正完成复杂任务：执行代码、浏览网页、操作文件、管理记忆、并行派生子 Agent。

官方定位：**"带电池的超级 Agent 运行时"**

## 解决的问题

传统 AI 框架的核心痛点：

| 痛点 | DeerFlow 的解决方案 |
|------|---------------------|
| 只能"对话"，没有真实执行环境 | 内置沙箱（Local/Docker/K8s），Agent 可执行 bash、读写文件 |
| 上下文窗口有限，长任务容易失控 | SummarizationMiddleware 自动压缩上下文 |
| 无法跨会话保留记忆 | 结构化 Facts 持久化，LLM 自动提取、置信度评分 |
| 单 Agent 处理复杂任务效率低 | 最多 3 个子 Agent 并行，ThreadPool 独立事件循环 |
| 工具能力固定，难以扩展 | Skills（Markdown 文件）+ MCP 协议双轨扩展 |
| 与 IM 渠道脱节 | 内置 Telegram/Slack/飞书/企业微信/微信接入 |

## 目标用户

- **开发者**：构建自定义 AI 工作流，需要完整的 Agent 执行基础设施
- **研究人员**：需要系统性多角度研究，利用并行子 Agent 提升效率
- **企业团队**：需要接入 IM 渠道，将 AI 能力集成到现有协作工具
- **AI 产品工程师**：需要一个可扩展、可观测、可生产部署的 Agent 框架

## 项目背景与版本

| 版本 | 里程碑 |
|------|--------|
| 1.0 | 基于 LangGraph 的深度研究工作流（原名 DeerFlow） |
| 2.0 (2026-02-28) | 完全重写为 Super Agent Harness，GitHub Trending #1 |

2.0 的核心变化：
- 从"深度研究专用框架"变为"通用 Super Agent 运行时"
- 引入 Middleware 架构
- 新增 Skills 系统、沙箱执行、长期记忆
- 支持 IM 渠道接入
- 支持自定义 Agent（SOUL.md）

## 与同类项目的差异

| 特点 | DeerFlow | Claude Code | Hermes Agent | nanobot |
|------|----------|-------------|--------------|---------|
| 定位 | Super Agent Harness（运行时框架）| 编程助手 CLI | 自我提升型个人 Agent | 轻量研究型 Agent |
| 核心创新 | Middleware 链 + Skills（Markdown）| 交互式终端编程 | 自我学习闭环 | 极简核心 + 插件 |
| 子 Agent | 并行 3 个，ThreadPool 隔离 | 无 | 支持，最多 3 个 | 支持 Spawn |
| 记忆系统 | 结构化 Facts + 置信度评分 | 无持久记忆 | MEMORY.md + USER.md | Dream 两阶段 |
| 前端 | 完整 Next.js WebUI | 纯 CLI | 纯 CLI + 消息网关 | CLI + WebUI |
| IM 接入 | 飞书/Slack/Telegram/企业微信/微信 | 无 | 20+ 平台 | 10+ 平台 |
| 技术框架 | LangGraph 1.0 | 自定义 | 无框架（纯 asyncio）| 事件总线 |

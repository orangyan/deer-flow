# 05 数据流

## 核心聊天请求流

```
1. 用户在 Web UI 输入消息
        ↓
2. Frontend (useThreadStream)
   → LangGraph SDK 发起 SSE 流请求
   POST /api/langgraph/threads/{thread_id}/runs/stream
        ↓
3. Nginx 将 /api/langgraph/* 路由到 Gateway (8001)
   Gateway 将请求转发到内嵌 LangGraph 运行时
        ↓
4. Gateway RunManager 收到请求
   → 创建 run，调用 run_agent()
        ↓
5. make_lead_agent(config) 构建 Agent：
   → 根据 config.yaml 解析模型名称
   → 加载可用工具（Sandbox + MCP + 内置工具）
   → 构建系统提示（注入 Skills 目录、Memory、子 Agent 说明）
   → 组装 18 个 Middleware 链
        ↓
6. Middleware 链 before_model 阶段（按序执行）：
   ThreadDataMiddleware   → 确保 workspace/uploads/outputs 目录存在
   UploadsMiddleware      → 将上传文件列表注入 HumanMessage
   SandboxMiddleware      → 获取/创建沙箱环境，记录 sandbox_id
   DanglingToolCallMiddleware → 修复悬空 ToolCall（防止 tool_call_id 不匹配错误）
   LLMErrorHandlingMiddleware → 归一化 LLM 调用失败
   GuardrailMiddleware    → 工具调用前授权检查（可选）
   SandboxAuditMiddleware → 安全审计日志
        ↓
7. LLM 调用循环（可能多次）：
   a. Model 处理历史消息 → 决定调用哪些工具（或生成最终答案）
   b. 执行工具调用（bash/web_search/read_file/task 等）
   c. 工具结果追加到消息历史
   d. 若调用 task() → 派生子 Agent 到线程池异步执行
   e. 重复直到无工具调用（最终答案）
        ↓
8. Middleware 链 after_model 阶段：
   ToolErrorHandlingMiddleware → 工具异常转 ToolMessage（不中断运行）
   SummarizationMiddleware → 超 token 时压缩旧消息
   TodoListMiddleware      → Plan 模式任务追踪
   TokenUsageMiddleware    → 收集 token 使用统计
   TitleMiddleware         → 首次完整对话后生成标题
   MemoryMiddleware        → 将对话入队（30s debounce 后异步提取 Facts）
   ViewImageMiddleware     → 注入图片 base64（视觉模型使用）
   DeferredToolFilterMiddleware → 隐藏延迟加载工具 schema
   SubagentLimitMiddleware → 截断超出 3 个的 task 工具调用
   LoopDetectionMiddleware → 检测重复工具调用循环
   ClarificationMiddleware → 拦截 ask_clarification，中断执行
        ↓
9. SSE 流式返回：
   StreamBridge 将 LangGraph events 转换为 SSE 格式
   → messages-tuple（增量消息）
   → values（状态快照）
   → custom（自定义事件：标题更新、产物更新等）
        ↓
10. Frontend 接收 SSE：
    → 逐 token 显示 AI 响应
    → 显示工具调用进度
    → 更新产物列表
```

## 子 Agent 执行流

```
Lead Agent 调用 task("分析 AWS", subagent_type="general-purpose") 工具
        ↓
SubagentLimitMiddleware 检查并发数 ≤ 3
        ↓
executor.execute_async(task)
        ↓
_scheduler_pool（3 workers）接收任务
        ↓
_execution_pool（3 workers）实际执行子 Agent
   - 每个子 Agent 在独立线程中运行独立事件循环（避免 asyncio 冲突）
   - 继承父 Agent 的 sandbox_state + thread_data（共享文件系统）
   - 加载各自的 Skills（可配置白名单过滤）
   - 独立的上下文（不看父 Agent 消息历史）
        ↓
Lead Agent 的 task() 工具每 5s 轮询检查状态
        ↓
子 Agent 完成 → SubagentResult{
    task_id, status, result,
    ai_messages（所有中间 AI 消息）,
    started_at, completed_at
}
        ↓
Lead Agent 收到所有子 Agent 结果
  → 汇总分析
  → 生成最终响应
```

## 文件上传流

```
用户拖拽/选择文件上传
        ↓
POST /api/threads/{id}/uploads（Gateway）
        ↓
验证文件路径安全性（normalize + prefix 检查，防目录穿越）
        ↓
存储到 .deer-flow/users/{user_id}/threads/{thread_id}/user-data/uploads/
        ↓
若是 PDF/PPT/Excel/Word
  → markitdown 转换为 .md 文件
  → 同目录保存（如 report.pdf → report.pdf.md）
        ↓
返回 virtual_path（/mnt/user-data/uploads/report.pdf）给前端
        ↓
用户下次发消息触发 Agent 运行时
  → UploadsMiddleware 将文件列表注入 HumanMessage 上下文
  → Agent 通过 read_file(/mnt/user-data/uploads/report.pdf.md) 读取转换后内容
```

## 记忆更新流

```
对话结束（Agent 生成最终响应）
        ↓
MemoryMiddleware 过滤消息：
  → 只保留（用户消息 + 最终 AI 消息），忽略工具调用中间步骤
  → 捕获当前 user_id（ContextVar）
        ↓
入队到 MemoryUpdateQueue（30s debounce 防频繁写入）
        ↓
30s 后触发后台异步执行：
  → 调用 LLM 分析对话
  → 提取新 Facts（content + category + confidence）
  → 更新 userContext / workContext 摘要
        ↓
原子写入 memory.json：
  temp_file = write to temp
  rename(temp_file, memory.json)  # 原子操作，防损坏
        ↓
下次 Agent 调用时：
  → MemoryMiddleware 读取 memory.json
  → 注入 <memory> 块到系统提示（top-15 Facts，最多 2000 token）
```

## SSE 事件流格式

前端接收的 SSE 事件类型：

```
event: messages/partial
data: {"messages": [{"role": "assistant", "content": "正在分析..."}]}

event: messages/complete
data: {"messages": [{"role": "assistant", "content": "完整响应"}]}

event: values
data: {"title": "AWS vs Azure 对比分析", "artifacts": ["/mnt/.../"]}

event: updates/node_started
data: {"node": "tools", "tool_call": {"name": "web_search", "args": {...}}}

event: updates/node_finished
data: {"node": "tools", "tool_result": "搜索结果..."}
```

## 错误处理流

```
LLM 调用失败
  → LLMErrorHandlingMiddleware 捕获
  → 归一化为可重试错误
  → 根据配置决定是否重试（circuit_breaker）
  → 超过重试上限 → 返回友好错误消息

工具调用失败
  → ToolErrorHandlingMiddleware 捕获
  → 转换为 ToolMessage（content="Error: ..."）
  → 注入消息历史，让 Agent 决策下一步
  → Agent 可以重试 / 换方案 / 报告无法完成

子 Agent 超时（15 分钟）
  → executor 取消子 Agent 任务
  → 返回 SubagentResult{status="timeout"}
  → Lead Agent 收到超时结果，汇总时注明
```

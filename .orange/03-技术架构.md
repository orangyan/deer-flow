# 03 技术架构

## 整体架构图

```
用户浏览器 / IM 客户端
        │
        ▼
┌─────────────────────────────────┐
│         Nginx (Port 2026)        │
│  /api/langgraph/* → Gateway      │
│  /api/*           → Gateway      │
│  /*               → Frontend     │
└─────────────────────────────────┘
        │
   ┌────┴─────┐
   ▼          ▼
Gateway API   Frontend
(Port 8001)   (Port 3000)
FastAPI       Next.js 16
   │
   ▼
Agent Runtime（内嵌于 Gateway）
RunManager → run_agent() → StreamBridge
LangGraph StateGraph
   │
   ├── Lead Agent（主 Agent）
   ├── Sub-Agents（ThreadPool，最多 3 个）
   ├── Sandbox（Local / Docker / K8s）
   └── Memory System（后台异步更新）
```

## 服务间通信

```
前端 → LangGraph SDK (WebSocket/SSE)
    → Nginx 代理 /api/langgraph/*
    → Gateway FastAPI
    → 内嵌 LangGraph InMemory checkpoint
    → Agent Runtime

前端 → REST API
    → Nginx 代理 /api/*
    → Gateway FastAPI
    → 文件上传 / 配置管理 / 会话管理
```

## 数据存储

| 数据类型 | 存储位置 |
|----------|----------|
| LangGraph checkpoint（消息历史）| SQLite / PostgreSQL |
| 用户上传文件 | `.deer-flow/users/{uid}/threads/{tid}/user-data/uploads/` |
| Agent 工作区 | `.deer-flow/users/{uid}/threads/{tid}/user-data/workspace/` |
| Agent 产物 | `.deer-flow/users/{uid}/threads/{tid}/user-data/outputs/` |
| 记忆数据 | `.deer-flow/users/{uid}/memory.json` |
| 扩展配置 | `extensions_config.json`（MCP + Skills 状态）|

## 安全设计

- 默认仅绑定 `127.0.0.1`（不暴露公网）
- 虚拟路径系统防目录穿越攻击
- `GuardrailMiddleware`：可插拔工具调用授权（Allowlist / OAP 协议）
- `SandboxAuditMiddleware`：工具调用安全审计日志
- 文件路径安全验证（normalize + 前缀检查）
- Docker 沙箱：Agent 代码在容器内执行，宿主机隔离

## 架构设计原则

1. **单向依赖**：`harness` 包不依赖 `app` 层（CI 测试强制保证）
2. **虚拟路径透明**：同一套代码，Local/Docker/K8s 无感切换
3. **嵌入式客户端**：`DeerFlowClient` 提供无 HTTP 的进程内访问，CI 自动验证与 Gateway API 对齐
4. **流式优先**：所有 Agent 响应通过 SSE 流式返回，前端逐 token 显示
5. **状态不可变**：LangGraph StateGraph，每步生成新状态，方便 checkpoint/replay
